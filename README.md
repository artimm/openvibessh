# openvibessh

**OpenVibeSSH** — утилита выдачи одноразового SSH-доступа ИИ-агентам (OpenCode, Claude Code и др.) в LXD-контейнерах: логин + пароль + sudo, без сертификатов и ключей. Встроенный TTL-планировщик автоматически закрывает доступ агенту, если он бездействует.

Одна команда — на хосте открывается меню работы с контейнерами, внутри контейнера — меню выдачи доступа. Скрипт сам определяет, где запущен.

## Зачем это нужно

ИИ-агенты выполняют произвольный код в вашей системе. OpenVibeSSH решает три задачи:

1. **Изоляция** — агент работает в контейнере LXD, а не на вашем сервере. Ошибка или вредоносное действие не затронет хост.
2. **Контроль доступа** — у каждого агента свой логин и пароль; sudo выдается осознанно (или не выдается); доступ можно отозвать в любой момент.
3. **Автоочистка** — забытые доступы не живут вечно: TTL-планировщик сам блокирует агента после N минут бездействия.

## Быстрый старт

На LXD-хосте (и в контейнере — команда одна и та же):

```bash
curl -fsSL https://raw.githubusercontent.com/artimm/openvibessh/main/openvibessh.sh | bash
```

Требуется интерактивный терминал (обычный SSH-сеанс). Без TTY меню недоступно — используйте подкоманды ниже. Если curl не установлен, скачайте файл любым способом (wget, из браузера) и запустите `bash openvibessh.sh`.

Запускать через `bash`, не `sh` (в скрипте используются возможности bash: mapfile, `[[ ]]`).

## Как это работает

```text
 +------------------+        LXD proxy          +---------------------+
 |   Ваш компьютер  |  host:2424 -> ct:22        |   LXD-хост          |
 |  OpenCode/агент  | =========================> |  [openvibessh]      |
 +------------------+   ssh login+password       |    |                |
                                              |  +--------------+   |
                                              |  | контейнер    |   |
                                              |  | sshd :22     |   |
                                              |  | агент (sudo?)|   |
                                              |  +--------------+   |
                                              +---------------------+
```

1. **На хосте** выбираете запущенный контейнер и внешний порт. Скрипт ставит/включает sshd внутри контейнера и создает LXD proxy-устройство `хост:порт -> контейнер:22`.
2. **Тут же из меню** создается агент: скрипт сам скачивает себя внутрь контейнера и выполняет `agent-add` (пользователь, пароль, sudo, TTL).
3. **Агент подключается** по `ssh <имя>@<ip-хоста> -p <порт>` из OpenCode/терминала.
4. **TTL-планировщик** (systemd-таймер, проверка каждые 2 минуты) следит за активностью: нет входов N минут — доступ закрывается по выбранной политике.

## TTL-планировщик (автоотключение)

Настройка по умолчанию и установка таймера одной командой:

```bash
bash openvibessh.sh ttl 30 lock
```

**30** — минут бездействия до отключения (по умолчанию 30).

**Политики** при срабатывании:

| Политика | Что делает |
|----------|-----------|
| `lock` (по умолчанию) | Блокирует пароль и sudo, обрывает сессии. Аккаунт остается — `agent <имя>` переоткрывает доступ с новым паролем |
| `locksudo` | Мягко: забирает только sudo, вход остается |
| `delete` | Жестко: пользователь удаляется, домашняя папка архивируется в `/home/opencode/archive` |

Активность = время последнего входа агента (`lastlog`) либо момент выдачи доступа. Проверки выполняет systemd-таймер `openvibessh-cron.timer` каждые 2 минуты; журнал автоотключений: `/var/log/openvibessh.log`; реестр агентов: `/etc/openvibessh/agents.list`.

В списке (`list`) видно, сколько минут осталось каждому агенту до автоотключения.

## Подкоманды (для автоматизации, работают без TTY)

```bash
# хост
openvibessh.sh open <контейнер> [порт]   # открыть доступ
openvibessh.sh ports                     # список открытых портов
openvibessh.sh close                     # закрыть доступ (выбор из списка)

# контейнер
openvibessh.sh agent <имя> [минут] [политика]      # интерактивная выдача
openvibessh.sh agent-add <имя> <пароль|-> <минуты> <политика> <no|askpass|nopasswd>
                                                   # неинтерактивная (так хост создает агента удаленно)
openvibessh.sh list                                # выданные доступы + остаток времени
openvibessh.sh ttl <минут> [политика]              # настройки по умолчанию + таймер
openvibessh.sh ssh                                 # установить/включить/перезапустить sshd
openvibessh.sh disable <имя>                       # немедленно отключить агента
openvibessh.sh install                             # прописать себя: /usr/local/bin + команда ovssh
```

Пример: выдать агенту `xbot` доступ на 60 минут с sudo без пароля:

```bash
openvibessh.sh agent-add xbot - 60 lock nopasswd
```

## Установка в систему

Внутри скрипта: `bash openvibessh.sh install` — скрипт копирует себя в `/usr/local/bin/openvibessh.sh` и создает алиас `ovssh`:

```bash
ovssh                    # меню (автоопределение хост/контейнер)
ovssh host               # меню хоста
ovssh open <CT> <порт>   # открыть доступ
ovssh agent <имя> 30 lock
ovssh list | ssh | disable <имя> | ttl <минут> [политика]
```

## Файлы

| Путь | Назначение |
|------|-----------|
| `/etc/openvibessh/agents.list` | реестр выданных доступов (имя, sudo, TTL, политика, статус) |
| `/etc/openvibessh/ttl.conf` | настройки TTL по умолчанию |
| `/var/log/openvibessh.log` | журнал автоотключений |
| `/etc/ssh/sshd_config.d/60-openvibessh.conf` | парольный вход + порт 22 |
| `/etc/sudoers.d/91-ovssh-<имя>` | sudo-правила агентов (`.disabled` после блокировки) |

## Безопасность

* Пароли генерируются криптографическим генератором (14 символов) либо задаются вами.
* sudo — отдельный выбор: `nopasswd` / `askpass` / `no` (по умолчанию — без sudo).
* Открытые порты видны в списке (`ports`) и закрываются одной командой (`close`).
* Скрипт требует root внутри контейнера и сам перезапускается через sudo.
* Ничего не удаляется молча: политика `delete` архивирует домашнюю папку агента.

## Требования

* LXD-хост с командой `lxc` (для режима хоста), Ubuntu 22.04/24.04 в контейнерах.
* Bash (не sh/dash), systemd в контейнере.
* Внутри контейнера для скачивания нужен curl или wget (скрипт сам поставит при необходимости).
