# openvibessh
## Меню (v1.5)

Одна команда — `curl -fsSL ... | bash` — открывает меню и полностью ведет за руку.

### На хосте

```text
 1) Открыть доступ контейнеру (порт + агент)
 2) Список открытых портов
 3) Закрыть доступ (удалить порт)
 0) Выход
```

Пункт 1 ведет за руку полностью: выбор контейнера → внешний порт → подготовка sshd → **предложение сразу создать агента** (имя, пароль или случайный, TTL, политика, sudo) — агент создается удаленно внутри контейнера, и в конце печатается готовая строка `ssh <имя>@<ip> -p <порт>`. Руками ничего выполнять не нужно.

Пункт 2 показывает все открытые порты (`контейнер: внешний -> 22`), пункт 3 закрывает доступ выбором номера.

### В контейнере

```text
 1) Выдать доступ агенту (логин + пароль + sudo + TTL)
 2) Список доступов и остаток времени
 3) Настроить TTL автоотключения
 4) Починить SSH (установить / включить / перезапустить)
 5) Отключить агента немедленно
 6) Установить скрипт в систему (команда ovssh)
 0) Выход
```

### Прямые команды (для автоматизации)

```bash
ovssh open <контейнер> <порт>    # хост: открыть доступ
ovssh ports / ovssh close        # хост: список / закрыть
ovssh agent <имя> [минут] [политика]   # контейнер: интерактивно
ovssh agent-add <имя> <пароль|-> <минуты> <политика> <no|askpass|nopasswd>  # контейнер: неинтерактивно
ovssh list / ssh / disable <имя> / ttl <минут> [политика] / install
```

## Быстрый старт — универсальная команда (curl или wget, или сама поставит curl)

```bash
bash -c 'U=https://raw.githubusercontent.com/artimm/openvibessh/main/openvibessh.sh;F=/tmp/ovs.sh;if command -v curl >/dev/null;then curl -fsSL "$U" -o "$F";elif command -v wget >/dev/null;then wget -qO "$F" "$U";else apt-get update -qq;apt-get install -y -qq curl;curl -fsSL "$U" -o "$F";fi;bash "$F"'
```

Скрипт сам определит, где запущен (LXD-хост или контейнер) и откроет нужный режим.

## Установка в систему (команда ovssh)

Внутри скрипта: `bash openvibessh.sh install` — пропишет себя в `/usr/local/bin/openvibessh.sh` и создаст алиас `ovssh`. Дальше везде коротко:

```bash
ovssh                      # меню / автоопределение
ovssh host                 # на LXD-хосте: контейнеры + проброс порта
ovssh agent <имя> 30 lock  # в контейнере: выдать доступ с TTL
ovssh list                 # выданные права + остаток времени
ovssh ssh                  # починить ssh
ovssh disable <имя>        # отключить агента
```

⚠️ Запускайте через `bash`, не `sh` — скрипт использует bash-функции (mapfile, [[ ]]), в dash они не работают.

Мини-скрипт выдачи SSH-доступа агентам (логин + пароль + sudo) в LXD-контейнерах. Без сертификатов — только логин и пароль. **Плюс планировщик TTL**: агент, в котором нет активности, автоматически отключается через заданное время.

## Быстрый старт — одна команда

```bash
curl -fsSL https://raw.githubusercontent.com/artimm/openvibessh/main/openvibessh.sh | bash
```

Скрипт **сам определяет, где запущен**:
* на **LXD-хосте** — покажет активные контейнеры, откроет порт;
* в **контейнере** — откроет интерактивное меню: выдать доступ агенту / список / TTL / починить SSH / отключить агента.

Работает и через `curl | bash`: скрипт сам перезапускает себя из файла, сохраняя интерактивные вопросы.

## Режимы (подробно)

Скрипт сам определяет, где запущен: на LXD-хосте (есть команда `lxc`) — режим **host**, внутри контейнера — режимы **agent** / **list** / **ttl** / **ssh** / **disable** / **cron**.

### 1. На хосте: показать контейнеры и открыть доступ

```bash
curl -fsSL https://raw.githubusercontent.com/artimm/openvibessh/main/openvibessh.sh -o ovssh.sh
bash ovssh.sh host
```

* Показывает **активные (RUNNING) LXD-контейнеры** — выбираете нужный.
* Спрашивает внешний порт (по умолчанию `2424`, проверяет занятость).
* Готовит `openssh-server` внутри контейнера (парольный вход разрешен).
* Добавляет проброс: `внешний порт хоста -> 22 контейнера`.

Аргументами: `bash ovssh.sh host <контейнер> <порт>`.

### 2. Внутри контейнера: выдать доступ агенту (с TTL)

```bash
curl -fsSL https://raw.githubusercontent.com/artimm/openvibessh/main/openvibessh.sh | bash -s -- agent <имя> 30 lock
```

* Создает пользователя `<имя>` с **паролем** (или генерирует случайный).
* Выдает **sudo** на выбор: `NOPASSWD`, sudo с запросом пароля, или без sudo.
* Включает `sshd` на обычном порту **22** с парольной аутентификацией.
* Ставит **TTL**: автоотключение через `30` минут простоя с политикой `lock`.

`минут` и `политика` можно не указывать — возьмутся из настроек по умолчанию (`ttl`). Повторный запуск `agent <имя>` **переоткрывает** доступ: новый пароль, сброс таймера, снятие блокировок.

### 3. Планировщик автоотключения (TTL)

Настройка значений по умолчанию + установка таймера (одной командой):

```bash
curl -fsSL https://raw.githubusercontent.com/artimm/openvibessh/main/openvibessh.sh | sudo bash -s -- ttl 30 lock
```

* **30** — минут без активности до отключения (по умолчанию 30).
* **Политики** что делать с «заснувшим» агентом:
  * `lock` (по умолчанию) — блокируется пароль и sudo, обрываются сессии. Аккаунт остается: повторный `agent <имя>` возвращает доступ с новым паролем.
  * `locksudo` — забирается только sudo, SSH-вход остается.
  * `delete` — полный отзыв: пользователь удаляется, домашняя папка архивируется в `/home/opencode/archive`.

**Как считается активность:** последнее время входа агента (`lastlog`) либо момент выдачи доступа, если входов еще не было. Проверка выполняется **systemd-таймером каждые 2 минуты** (`openvibessh-cron.timer`), сам скрипт при установке копируется в `/usr/local/bin/openvibessh.sh`. Все автоотключения пишутся в `/var/log/openvibessh.log`.

Ручное отключение немедленно: `bash openvibessh.sh disable <имя>`.

### 4. Внутри контейнера: список выданных прав

```bash
curl -fsSL https://raw.githubusercontent.com/artimm/openvibessh/main/openvibessh.sh | bash -s -- list
```

Таблица: агент, sudo, TTL, политика, статус (ACTIVE/DISABLED), **сколько минут осталось** до автоотключения. Ниже — журнал автоотключений и эффективные права каждого агента (`sudo -l -U`).

### 5. Починить ssh внутри контейнера

```bash
curl -fsSL https://raw.githubusercontent.com/artimm/openvibessh/main/openvibessh.sh | bash -s -- ssh
```

Если ssh не установлен — установит; выключен — включит; запущен — перезапустит; проверит, что порт 22 слушается.

## Подключение агента

```bash
ssh <имя>@<IP_хоста> -p <внешний порт>
```

## Отзыв доступа

Немедленно и полностью: `bash openvibessh.sh disable <имя>` + на хосте `lxc config device remove <контейнер> ovssh-<порт>`. Журнал выданных доступов: `/etc/openvibessh/agents.list`, настройки TTL: `/etc/openvibessh/ttl.conf`.
